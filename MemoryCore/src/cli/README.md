# memory-wamf CLI

The `openclaw memory-wamf` command namespace, with offline data management tools.

## seed: import past conversations

Imports past conversations from a JSON file into the memory pipeline and runs the full L0→L1→L2→L3 flow. Useful for:

- loading existing conversation data into the memory system
- batch-testing memory extraction
- migrating/restoring memory data

### Usage

```bash
openclaw memory-wamf seed --input <file> [options]
```

### Options

| Option | Required | Description |
|------|------|------|
| `--input <file>` | ✅ | input JSON file path |
| `--output-dir <dir>` | — | output directory (a timestamped directory is generated by default) |
| `--session-key <key>` | — | fallback session key (used when the input data has none) |
| `--config <file>` | — | config override file (JSON, deep-merged with the plugin config in openclaw.json) |
| `--strict-round-role` | — | strictly require every round to contain a user and an assistant message |
| `--yes` | — | skip interactive confirmations (such as confirming automatic timestamp filling) |

### Examples

```bash
# basic usage
openclaw memory-wamf seed --input conversations.json

# custom output directory
openclaw memory-wamf seed --input data.json --output-dir ./seed-output

# custom config override (e.g. different pipeline parameters)
openclaw memory-wamf seed --input data.json --config seed-config.json

# skip all confirmations
openclaw memory-wamf seed --input data.json --yes

# strict mode + custom config
openclaw memory-wamf seed --input data.json --config seed-config.json --strict-round-role --yes
```

### Input file format

Two JSON formats are supported:

#### Format A: wrapped in an object

```json
{
  "sessions": [
    {
      "sessionKey": "user-alice",
      "sessionId": "conv-001",
      "conversations": [
        [
          { "role": "user", "content": "Hi", "timestamp": 1711929600000 },
          { "role": "assistant", "content": "Hi! How can I help?", "timestamp": 1711929601000 }
        ],
        [
          { "role": "user", "content": "What's the weather like today?" },
          { "role": "assistant", "content": "It's sunny today, good for going out." }
        ]
      ]
    }
  ]
}
```

#### Format B: top-level array

```json
[
  {
    "sessionKey": "user-alice",
    "conversations": [
      [
        { "role": "user", "content": "Hi" },
        { "role": "assistant", "content": "Hi!" }
      ]
    ]
  }
]
```

#### Fields

| Field | Type | Required | Description |
|------|------|------|------|
| `sessionKey` | string | ✅ | session identifier (e.g. a user ID or channel name) |
| `sessionId` | string | — | conversation instance ID (one sessionKey can have several sessionIds) |
| `conversations` | message[][] | ✅ | array of conversation rounds; each round is a group of messages |
| `role` | string | ✅ | message role: `user` or `assistant` |
| `content` | string | ✅ | message content |
| `timestamp` | number \| string | — | timestamp: epoch milliseconds or an ISO 8601 string. When missing, seed offers to fill it in automatically |

### Config override

`--config` takes a JSON file that is **deep-merged two levels deep** with the plugin config in `openclaw.json`:

- a top-level key that is an object on both sides → shallow merge (fields not overridden keep their base values)
- any other type → replaced

Common case: use more aggressive pipeline parameters during seed to speed things up:

```json
{
  "pipeline": {
    "everyNConversations": 3,
    "enableWarmup": false,
    "l1IdleTimeoutSeconds": 2,
    "l2DelayAfterL1Seconds": 1,
    "l2MinIntervalSeconds": 1,
    "l2MaxIntervalSeconds": 10
  }
}
```

To seed into a separate MongoDB database (connection taken from the `MONGODB_ENDPOINT` / `MONGODB_USER` / `MONGODB_PASSWORD` env vars; set `MONGODB_DATABASE=my_seed_test_db`):

```json
{
  "storeBackend": "mongodb",
  "pipeline": {
    "everyNConversations": 3,
    "enableWarmup": false,
    "l1IdleTimeoutSeconds": 2
  }
}
```

### Output directory layout

```
<output-dir>/
├── conversations/          — L0 JSONL files
├── records/                — L1 JSONL files
├── scene_blocks/           — L2 scene blocks
├── vectors.db              — SQLite vector database (sqlite backend only)
├── .metadata/
│   ├── manifest.json       — metadata (store binding + seed run record)
│   └── checkpoint.json     — pipeline progress
└── .backup/                — rolling backups
```

When seed finishes, `manifest.json` records the run:

```json
{
  "version": 1,
  "createdAt": "2026-04-01T22:00:00.000Z",
  "store": {
    "type": "sqlite",
    "sqlite": { "path": "vectors.db" }
  },
  "seed": {
    "inputFile": "conversations.json",
    "sessions": 3,
    "rounds": 42,
    "messages": 128,
    "startedAt": "2026-04-01T22:00:00.000Z",
    "completedAt": "2026-04-01T22:05:30.000Z"
  }
}
```
